# PRD: 오늘의 할일 (Today's To-Do) 웹페이지

- 문서 버전: v0.1 (설계 단계)
- 작성일: 2026-11-02
- 상태: Draft — 구현 전 설계 문서

---

## 1. 개요

### 1.1 배경
하루 동안 해야 할 일을 빠르게 적고, 체크하고, 하루가 끝날 때 얼마나 완료했는지 확인할 수 있는 가볍고 단순한 웹페이지가 필요하다. 복잡한 프로젝트 관리 도구가 아니라 **"오늘"에 집중**하는 개인용 할일 목록이다.

### 1.2 목표
- 3초 안에 할일을 추가할 수 있는 단순한 UX
- 별도 설치·로그인 없이 브라우저에서 바로 사용
- 새로고침·브라우저 재시작 후에도 데이터 유지
- 오늘의 진행률을 한눈에 확인

### 1.3 비목표 (Out of Scope, v1)
- 회원가입/로그인, 서버 동기화, 여러 기기 간 공유
- 팀 협업, 할일 할당
- 반복 일정, 캘린더 연동, 푸시 알림
- 하위 할일(서브태스크)

## 2. 대상 사용자

| 페르소나 | 설명 | 핵심 니즈 |
|---|---|---|
| 직장인 | 출근 후 오늘 할 업무를 정리 | 빠른 입력, 우선순위 구분 |
| 학생 | 과제·공부 계획 관리 | 완료 체크의 성취감, 진행률 |
| 일반 사용자 | 장보기·집안일 등 생활 할일 | 단순함, 모바일에서도 편한 사용 |

---

## 3. 사용자 스토리

1. 사용자로서, 할일을 입력하고 Enter를 누르면 목록에 바로 추가되길 원한다.
2. 사용자로서, 체크박스를 눌러 할일을 완료 처리하거나 되돌리고 싶다.
3. 사용자로서, 잘못 적은 할일을 수정하거나 삭제하고 싶다.
4. 사용자로서, 중요한 할일에 우선순위를 표시하고 싶다.
5. 사용자로서, 전체/진행 중/완료 항목을 필터링해서 보고 싶다.
6. 사용자로서, 오늘 몇 개 중 몇 개를 끝냈는지 진행률로 보고 싶다.
7. 사용자로서, 완료한 항목을 한 번에 정리하고 싶다.
8. 사용자로서, 날짜가 바뀌면 끝내지 못한 할일을 오늘로 가져올지 선택하고 싶다.

## 4. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = MVP 권장, **P2** = 이후 버전

### 4.1 할일 관리 (CRUD)
| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| F-01 | 할일 추가 | 입력창 + Enter 또는 "추가" 버튼. 공백만 입력 시 무시. 최대 100자 | P0 |
| F-02 | 완료 토글 | 체크박스 클릭 시 완료/미완료 전환. 완료 항목은 취소선 + 흐리게 표시 | P0 |
| F-03 | 할일 수정 | 텍스트 더블클릭(모바일: 수정 버튼) → 인라인 편집. Enter 저장, Esc 취소 | P0 |
| F-04 | 할일 삭제 | 항목별 삭제 버튼. 삭제 후 5초간 "실행 취소" 토스트 제공 | P0 |
| F-05 | 우선순위 | 높음/보통/낮음 3단계, 색상 점으로 표시. 기본값 "보통" | P1 |
| F-06 | 순서 변경 | 드래그 앤 드롭으로 순서 변경 | P2 |

### 4.2 보기 및 정리
| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| F-07 | 필터 | 전체 / 진행 중 / 완료 탭 | P0 |
| F-08 | 진행률 | "3 / 5 완료" 텍스트 + 프로그레스 바 | P0 |
| F-09 | 완료 항목 일괄 삭제 | "완료 항목 지우기" 버튼 (확인 후 실행) | P1 |
| F-10 | 정렬 | 미완료 우선 → 우선순위 높은 순 → 생성 순 | P1 |
| F-11 | 빈 상태 | 할일이 없을 때 안내 문구 표시 ("오늘 할 일을 추가해 보세요") | P0 |

### 4.3 날짜 처리
| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|

| F-14 | 지난 기록 보기 | 이전 날짜의 할일 목록 조회 (읽기 전용) | P2 |

## 6. 화면 설계

### 6.1 레이아웃 (와이어프레임)

```
┌─────────────────────────────────────────┐
│  오늘의 할일                              │
│  2026년 11월 2일 (월)                     │
│  ███████████░░░░░░░  3 / 5 완료 (60%)    │
├─────────────────────────────────────────┤
│ ┌─────────────────────────────┐ ┌─────┐ │
│ │ 할 일을 입력하세요...        │ │ 추가 │ │
│ └─────────────────────────────┘ └─────┘ │
│  우선순위: ( ) 높음 (•) 보통 ( ) 낮음      │
├─────────────────────────────────────────┤
│  [전체]  진행 중   완료                    │
├─────────────────────────────────────────┤
│  ☐ ● 기획서 초안 작성              ✎  ✕  │
│  ☐ ● 장보기                        ✎  ✕  │
│  ☑ ● ~~운동 30분~~                  ✎  ✕  │
├─────────────────────────────────────────┤
│  남은 할일 2개          [완료 항목 지우기]  │
└─────────────────────────────────────────┘
```

### 6.2 주요 상태
- **빈 상태**: 목록 영역에 일러스트/아이콘 + 안내 문구
- **편집 상태**: 해당 항목이 입력창으로 전환, 다른 항목 조작 비활성화
- **삭제 직후**: 화면 하단 토스트 "삭제됨 · 실행 취소"
- **날짜 변경 감지**: 상단 배너 "어제 못 끝낸 할일 2개가 있어요. [오늘로 가져오기] [버리기]"
- **모두 완료**: 진행률 100% 시 축하 메시지

### 6.3 키보드 단축키
| 키 | 동작 |
|---|---|
| `Enter` (입력창) | 할일 추가 |
| `Enter` / `Esc` (편집 중) | 저장 / 취소 |
| `Space` (체크박스 포커스) | 완료 토글 |
| `Delete` (항목 포커스) | 삭제 |
| `/` | 입력창으로 포커스 이동 |

## 7. 데이터 모델

### 7.1 Todo
```ts
interface Todo {
  id: string;            // crypto.randomUUID()
  text: string;          // 1~100자, 앞뒤 공백 제거
  completed: boolean;
  priority: 'high' | 'medium' | 'low';
  date: string;          // 'YYYY-MM-DD' (로컬 시간 기준)
  createdAt: number;     // epoch ms
  completedAt: number | null;
  order: number;         // 정렬 순서 (P2 드래그용)
}
```

### 7.2 저장 구조 (localStorage)
| 키 | 값 |
|---|---|
| `todolist:v1:todos` | `Todo[]` JSON |
| `todolist:v1:lastOpenedDate` | `'YYYY-MM-DD'` |
| `todolist:v1:filter` | `'all' \| 'active' \| 'completed'` |

- 키에 버전(`v1`)을 포함해 이후 스키마 변경 시 마이그레이션 가능하도록 한다.
- JSON 파싱 실패 시 기존 값을 `todolist:v1:backup`으로 옮기고 빈 목록으로 시작한다.

## 8. 기술 설계

### 8.1 기술 스택 (권장)
- **HTML + CSS + Vanilla JavaScript (ES Modules)**
- 빌드 도구 없이 `index.html`을 브라우저로 열면 동작
- 사유: 기능 규모가 작아 프레임워크 오버헤드가 불필요하고, 배포가 간단함 (GitHub Pages 등 정적 호스팅)

### 8.2 폴더 구조 (예정)
```
todolist/
├── prd.md            # 본 문서
├── index.html        # 마크업
├── css/
│   └── style.css     # 스타일, 라이트/다크 테마 변수
└── js/
    ├── app.js        # 진입점, 이벤트 바인딩
    ├── store.js      # 상태 관리 + localStorage 입출력
    ├── render.js     # DOM 렌더링
    └── utils.js      # 날짜 포맷, id 생성 등
```

### 8.3 아키텍처
단방향 데이터 흐름을 따른다.

```
사용자 이벤트 → app.js (액션 디스패치)
             → store.js (상태 변경 → localStorage 저장)
             → render.js (상태 기반으로 화면 다시 그림)
```

- **store.js** 공개 API: `getState()`, `addTodo(text, priority)`, `toggleTodo(id)`, `updateTodo(id, patch)`, `deleteTodo(id)`, `restoreTodo(todo)`, `clearCompleted()`, `setFilter(filter)`, `carryOverFrom(date)`, `subscribe(listener)`
- **render.js**: 상태를 받아 목록·진행률·필터 탭을 갱신. 텍스트는 `textContent`로만 삽입
- 날짜는 항상 **로컬 시간대** 기준 `YYYY-MM-DD`로 계산 (UTC 사용 시 자정 근처 오류 발생 주의)

## 9. 예외 및 엣지 케이스

| 상황 | 처리 |
|---|---|
| 공백만 입력 | 추가하지 않음, 입력창 흔들림 효과 |
| 100자 초과 | 입력 제한(`maxlength`) + 남은 글자 수 표시 |
| 편집 중 텍스트를 모두 지움 | 저장 시 삭제 확인 |
| 여러 탭 동시 사용 | `storage` 이벤트로 다른 탭 변경 사항 반영 |
| 자정이 지난 상태로 페이지가 열려 있음 | 페이지 포커스 시 날짜 재확인 → F-13 배너 |
| localStorage 용량 초과/차단 | F-16 처리 |
